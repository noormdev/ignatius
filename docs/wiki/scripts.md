# scripts

## What it does

[`scripts/`](../../scripts) holds standalone Bun scripts run directly with `bun scripts/<name>.ts`, not imported by application code. They fall into three groups: one required build post-processing step (`stable-names.ts`), one one-time data-migration script (`convert-yaml-to-md.ts`), and four dev-time tools for synthetic model generation, performance measurement, and manual visual/diagnostic inspection (`gen-synthetic-model.ts`, `perf-harness.ts`, `probe.ts`, `screenshot.ts`).

## Artifacts

No user-facing Claude Code skill/command artifacts in this domain.

## CLI code

- [`scripts/stable-names.ts`](../../scripts/stable-names.ts) — post-build step that copies the content-hashed `index-*.js`/`index-*.css` files in `dist/static/` to stable names `index.js`/`index.css`. Reads `dist/static/index.html` to find the authoritative hashed filenames via regex on the `src=`/`href=` attributes; falls back to a `Bun.Glob('index-*.js'/'index-*.css')` scan only if the HTML match fails. Exits with code 1 and an error message if either the JS or the CSS file can't be found — the two are checked independently, so it exits on the first missing one rather than waiting for both to be absent. Required before `bun build --compile` because compiled binaries need import paths known at compile time.
- [`scripts/convert-yaml-to-md.ts`](../../scripts/convert-yaml-to-md.ts) (257 lines) — one-time migration script that reads a hardcoded input `tmp/sample_model.yaml`, parses it with the `yaml` package, and writes one markdown file per entity into `models/<group>/<entity>.md`. Derives an IDEF1X classification per entity (`Subtype`, `Associative`, `Dependent`, `Classifier`, or `Independent`) from subtype membership, identifying-relationship count, and column shape; derives a `group` (`reference`, `transactional`, `catalog`, `identity`) from the entity's declared `groups` or by walking up identifying parents. Emits YAML frontmatter (`entity`, `classification`, `group`, `pk`, `columns`, optional `ak`/`subtypes`/`relationships`) plus a markdown body with `## Subtypes`, `## Values`, and `## Constraints` sections built from the source YAML.
- [`scripts/probe.ts`](../../scripts/probe.ts) (95 lines) — ad-hoc diagnostic script. Opens a native `webview-bun` window against a URL (default `http://localhost:3777`), waits for a `.react-flow__node` element to appear, then serializes visible node positions (parsed from each element's CSS `transform`) and edge count into a JSON report printed to stdout. Has a 60-second safety-quit timer and a 30-second wait-for-node timeout. Exits 0 only if a `report` payload was produced.
- [`scripts/screenshot.ts`](../../scripts/screenshot.ts) (82 lines) — snapshot helper that opens a native `webview-bun` window against a URL (default `http://localhost:3777`), waits up to 8 seconds for `.card svg` to appear, then serializes every `<svg>` inside a `.card` on the page (wrapped with an XML declaration and a dark background `<rect>`) and writes each to a file under an output directory (default `/tmp/ignatius-shots`, second CLI arg). Filenames are sanitized to `[a-z0-9._-]` and prefixed with a zero-padded index. Uses `writeFileSync` synchronously inside the `webview.bind` callback specifically to avoid an IPC deadlock in `webview-bun` that affects `await`ed writes from a bind handler. Exits 0 only if at least one file was written.
- [`scripts/gen-synthetic-model.ts`](../../scripts/gen-synthetic-model.ts) (428 lines) — synthetic IDEF1X model generator for perf testing. CLI: `bun scripts/gen-synthetic-model.ts [--n 300] [--out tmp/my-model]`. Writes a complete model root: `ignatius.yml` (with a hardcoded dark/light theme), one `groups/<id>.md` file per group across 6 fixed groups (`core`, `catalog`, `sales`, `finance`, `ops`, `reporting`, distributed via fixed weights `[0.18, 0.20, 0.22, 0.18, 0.16, 0.06]`), and one entity markdown file per generated entity under `data/<group>/`. Always includes 3 hardcoded subtype clusters (`Party` → `Person`/`Organization`, `Product` → `PhysicalProduct`/`DigitalProduct`, `Channel` → `WebChannel`/`PartnerChannel`). Non-cluster entities get 1–3 FK relationships wired via a hub-and-peer strategy targeting ~1.4–1.8× edges per node while avoiding cycles. Default output directory: `tmp/synthetic-model-<n>/`.
- [`scripts/perf-harness.ts`](../../scripts/perf-harness.ts) (215 lines) — Playwright-based render latency measurement harness. CLI: `bun scripts/perf-harness.ts [--model <dir>] [--n <count>] [--port <port>] [--runs <k>] [--mode organic|hierarchical]`. Without `--model`, first spawns `bun scripts/gen-synthetic-model.ts --n <N> --out tmp/synthetic-model-<N>` as a subprocess. Measures `parseModels()` timing directly via a dynamic import of `../src/model/parse`, spawns `bun src/cli/cli.ts serve <modelDir> --port <PORT>` as a subprocess server, fetches `/api/model` for payload byte size, then drives a headless Chromium page via `playwright` to measure `time-to-layoutstop` (navigation start until `window.__IGNATIUS_PERF__` is stamped) and `time-to-interactive` (layoutstop + a 200ms settle). Clears the `ignatius-layout-positions` `localStorage` key before each measured run so ELK always runs cold; `--mode` optionally forces `ignatius-layout-mode` in `localStorage` before navigation. Uses a 10-minute `waitForFunction` timeout to accommodate large (300+ node) graphs. Prints a fixed-width ASCII report table to stdout. Not run by `bun run test` or CI.

## Coupling

- [`scripts/stable-names.ts`](../../scripts/stable-names.ts) is wired into [`package.json`](../../package.json)'s `build:stable-names` script, which `build:cli` depends on; it is also invoked directly as a CI step in [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) and [`.github/workflows/release-please.yml`](../../.github/workflows/release-please.yml). It reads `dist/static/index.html`, so any change to how the frontend/build pipeline ([`src/app/`](../../src/app)) names or references its hashed bundle entrypoints in the emitted HTML can break its regex match.
- [`scripts/gen-synthetic-model.ts`](../../scripts/gen-synthetic-model.ts) is invoked as a subprocess by [`test/checks/test-synthetic-model.ts`](../../test/checks/test-synthetic-model.ts) (run by `bun run test` and CI), by two [`test/visual/`](../../test/visual) scripts (`test-cp5b-edge-paint-on-load.ts`, `test-cp2-preset-layout.ts`), and by [`scripts/perf-harness.ts`](../../scripts/perf-harness.ts). Its emitted entity/group markdown frontmatter schema (`entity`, `group`, `pk`, `columns`, `relationships`, `subtypes`) must stay parseable by the parser domain's `parseModels()` ([`src/model/parse.ts`](../../src/model/parse.ts)) — `test-synthetic-model.ts` asserts exactly that.
- [`scripts/convert-yaml-to-md.ts`](../../scripts/convert-yaml-to-md.ts) writes into `models/<group>/<entity>.md` using the same entity frontmatter shape the parser domain expects, and its role as the old-format migration path is referenced from the skill domain's design/spec docs ([`docs/design/ignatius-modeling-skill.md`](../design/ignatius-modeling-skill.md), [`docs/spec/ignatius-modeling-skill.md`](../spec/ignatius-modeling-skill.md)) as the tool that already covers YAML→markdown migration.
- [`scripts/perf-harness.ts`](../../scripts/perf-harness.ts) imports `parseModels` directly from the parser domain ([`src/model/parse.ts`](../../src/model/parse.ts)), spawns the cli domain's `src/cli/cli.ts serve` subcommand, and reads the `window.__IGNATIUS_PERF__` global stamped by the frontend/app domain in [`src/app/views/graph/GraphView.tsx`](../../src/app/views/graph/GraphView.tsx) — a rename or removal of that global breaks the harness silently (it would just hang until the 10-minute timeout).
- [`scripts/probe.ts`](../../scripts/probe.ts) and [`scripts/screenshot.ts`](../../scripts/screenshot.ts) both target a running dev server (default `http://localhost:3777`, matching the `dev`/`dev:cli` [`package.json`](../../package.json) scripts) and depend on specific DOM structure in the frontend/app domain to find their targets.
- No [`package.json`](../../package.json) script wires up `probe.ts`, `screenshot.ts`, `gen-synthetic-model.ts`, `perf-harness.ts`, or `convert-yaml-to-md.ts` directly — only `build:stable-names` → `stable-names.ts` is a first-class [`package.json`](../../package.json) script; the rest are invoked ad hoc via `bun scripts/<name>.ts` per each script's own usage comment, or as subprocesses from test files.

## Conventions worth knowing

- Scripts here are plain top-level-await Bun scripts, not wrapped in a `main()` function or a CLI framework (`citty`, used by the actual CLI domain, is not used here) — CLI args are read ad hoc via `process.argv.indexOf(flag)` helpers — `argValue` is duplicated identically in `gen-synthetic-model.ts` and `perf-harness.ts`, while `argFlag` exists only in `perf-harness.ts`.
- `probe.ts` and `screenshot.ts` both use the `webview-bun` devDependency to drive a native webview window rather than Playwright — `perf-harness.ts` is the only script in this domain that uses the `playwright` devDependency. `probe.ts`'s DOM selectors (`.react-flow__node`, `.react-flow__edge`) target React Flow class names, but the frontend/app domain's graph is Cytoscape.js (confirmed by `cytoscape`/`cytoscape-navigator` imports and CSS in [`src/app/`](../../src/app)), which does not render nodes as individually classed `.react-flow__node` DOM elements — this script's selectors do not match the current graph implementation.
- [`scripts/screenshot.ts`](../../scripts/screenshot.ts)'s bind handler uses synchronous `writeFileSync` rather than `await`ed Bun file writes, with an inline comment explaining this sidesteps an IPC deadlock specific to `webview-bun`.
